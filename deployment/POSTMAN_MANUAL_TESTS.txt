BACKUP API (VBoxManage Snapshots)
================================================================================

8.1 Create backup

Method: POST
URL: http://localhost:6060/api/v1/backups
Headers: Content-Type: application/json
Body:
{
  "vmId": "{vm_id}",
  "serviceEnvironmentId": "66666666-6666-6666-6666-666666666666",
  "notes": "Before upgrade"
}
Response 201:
{
  "id": "uuid",
  "vmId": "uuid",
  "serviceEnvironmentId": "uuid",
  "status": "COMPLETED",
  "filePath": "backup-1720647000000",
  "sizeMb": 0,
  "type": "MANUAL",
  "notes": "Before upgrade",
  "createdAt": "2026-07-10T22:00:00Z",
  "updatedAt": "2026-07-10T22:00:00Z",
  "restoredAt": null
}
Response 400: VM must be RUNNING / VM has no VirtualBox name yet
Response 404: VM not found
Note: VM must be RUNNING. Snapshot name is auto-generated (backup-{timestamp}).

8.2 Get all backups

Method: GET
URL: http://localhost:6060/api/v1/backups
Headers: none
Body: none
Response 200: Array of BackupResponseDto

8.3 Get backup by id

Method: GET
URL: http://localhost:6060/api/v1/backups/{id}
Headers: none
Body: none
Response 200: BackupResponseDto
Response 404: Backup not found

8.4 Restore backup

Method: POST
URL: http://localhost:6060/api/v1/backups/{id}/restore
Headers: none
Body: none
Response 200: BackupResponseDto with status=RESTORED, restoredAt set
Response 400: Backup not completed / VM not provisioned
Response 404: Backup not found
Response 500: Restore failed
Note: Restores the VM to the snapshot state via VBoxManage snapshot restore.

8.5 Delete backup

Method: DELETE
URL: http://localhost:6060/api/v1/backups/{id}
Headers: none
Body: none
Response 204: No content
Response 404: Backup not found
Note: If backup is COMPLETED, the VBoxManage snapshot is also deleted.

================================================================================
WEB SSH GATEWAY (WebSocket)
================================================================================

Connect to a VM's SSH shell interactively via WebSocket.

Endpoint:
  ws://localhost:6060/ws/ssh/{vmId}

Protocol: WebSocket (text frames)

How it works:
  1. Open WebSocket connection to ws://localhost:6060/ws/ssh/{vmId}
  2. Server connects to the VM via JSch using Vagrant SSH config
  3. Send text frames = keystrokes to the VM shell
  4. Receive text frames = terminal output from the VM
  5. Close WebSocket = close SSH session

Frontend usage (JavaScript):
  const ws = new WebSocket("ws://localhost:6060/ws/ssh/{vmId}");
  ws.onmessage = (e) => { /* e.data = terminal output */ };
  ws.send("ls -la\n");  // send command

Requirements:
  - VM must be RUNNING
  - VM must have been provisioned (vboxName set)

Note: This replaces the old POST /api/v1/vms/{id}/ssh/execute endpoint.
The REST endpoint still works for single-command execution.
The WebSocket endpoint is for interactive terminal sessions.
